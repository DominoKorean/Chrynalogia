# Chrynalogia 구조 안정화 설계

작성일: 2026-10-13
기준 커밋: `809847d` (`first commit`)
상태: 사용자 검토 대기. 제품 코드 구현은 아직 시작하지 않음.

## 목적과 완료 기준

사용자는 앞선 코드 분석에 따라 Superpowers로 기존 코드를 개선하도록 요청했다. 기존 Java·Android 네이티브 View와 사용자의 UI를 유지하면서 설정 저장, 세션 수명, 파일 처리, 회귀 검사의 신뢰성을 높인다. 새로운 사용자 기능을 추가하지 않는다.

완료는 다음 조건으로 판단한다.

- 오래된 설정 객체나 파일 가져오기 작업이 다른 작업의 최신 설정을 덮어쓰지 않는다.
- 항상/수동 실행, 알림 권한 거부, 재부팅, 서비스 종료, 테마·언어 변경의 상태 전이가 테스트로 고정된다.
- 현재 KitSlider를 검사할 수 있으며 기기 검사 실패 시 원래 앱 설정과 시스템 설정을 복원한다.
- 연속 라인 입력이 메뉴 창 재생성과 카메라 탐색을 입력 횟수만큼 일으키지 않는다.
- 잘못된 파일·메타데이터가 앱을 중단시키지 않으며 사용자 오류는 한국어·영어 리소스로 표시한다.
- 기존 기하·대비 단위 검사, 새 회귀 검사, debug 빌드와 lint가 통과한다. 실행하지 못한 기기 검사는 명시한다.

## 접근 방식

선택한 방식은 기존 기능별 클래스의 경계를 보강하는 점진적 개선이다. SharedPreferences 저장소와 패키지·설치 식별자를 유지한다. 상태 계산과 파일 관리를 분리하고 호출부를 단계적으로 옮긴다.

대안인 전체 프레임워크 전환은 카메라 오버레이와 기존 UI의 회귀 범위가 크므로 적용하지 않는다. 개별 증상만 고치는 방식은 설정 덮어쓰기와 세션 판단 중복을 남기므로 선택하지 않는다.

## 보존할 계약

- Java 17, compile/target SDK 37, min SDK 34를 유지한다. 새 런타임 라이브러리는 추가하지 않는다.
- applicationId와 namespace는 `dev.chrynalogia.probe`, 설정 저장소 이름은 `probe`를 유지한다. 이번 구조 개선에서 버전 번호는 변경하지 않는다.
- 삼성 카메라의 실제 `camera_preview` 좌표를 사용한다. 임의의 화면 비율로 좌표를 추정하지 않는다.
- 그리드 창은 `TYPE_ACCESSIBILITY_OVERLAY`와 `NOT_TOUCHABLE | NOT_FOCUSABLE`을 유지한다. 메뉴·팝업 창만 입력을 받는다.
- 잠금, 화면 꺼짐, 다른 앱, 촬영 미리보기가 없는 화면에서는 그리드를 숨긴다. 접근성 연결과 실행 활성 상태를 구분한다.
- 앱의 명시적인 실행과 재진입은 기존 실행 동작을 유지한다. 테마·언어·화면 회전으로 Activity가 재생성되는 것만으로 중지된 수동 세션이 다시 시작되어서는 안 된다.
- 수동 세션은 알림 권한과 실제 foreground service 실행을 필요로 한다. 재부팅이나 서비스 종료 후 자동 복구하지 않는다.
- `DESIGN.md`와 `AGENTS.md`의 Figma 배치, Grid/Line/Settings 탭, 두 열 카드, 커스텀 칸 수 입력의 예약 공간, One UI SVG 아이콘, 앱 로고를 유지한다.
- 한국어·영어·시스템 언어와 시스템/밝게/어둡게 테마를 앱·카메라 설정에 유지한다.
- 기본값은 흰색, 두께 1.2dp, 불투명도 90%, 아웃라인 없음이다. 아웃라인은 기존 대비 계산을 사용한다.
- 기존 9종·커스텀 직각 격자, 회전·반전, 다중 선택, 가져온 파일의 비율 유지·늘리기를 보존한다. 커스텀 칸 수는 1~16이다.
- 단일 `golden_ratio`는 지원 목록에 복귀시키지 않는다. 기존 선택은 `golden_grid`로 이전한다.
- 가져오기는 파일당 4MB, 최대 12개, 비트맵 긴 변 최대 1024픽셀 수준의 샘플링과 앱 내부 저장을 유지한다. 추가 저장소·카메라·마이크·네트워크 권한을 요청하지 않는다.

## 1. 설정 저장과 데이터 검증

`GridSettings`는 현재 설정을 읽는 객체로 남기되, 변경 항목을 지정하는 저장 경로를 사용한다. 여러 항목이 의미상 하나의 변경인 경우 함께 저장한다. 예를 들어 색상 프리셋은 색·커스텀 선택 여부·아웃라인을 하나의 변경으로 처리한다.

전체 스냅샷을 다시 저장하는 제품 코드 호출을 제거한다. 파일 추가·삭제와 선택 목록 변경은 같은 저장 경로에서 최신 목록을 읽고 갱신하도록 직렬화한다. 가져오기 변환 중 설정 잠금을 유지하지 않는다. 변환이 끝난 시점에 개수 제한과 최신 다중 선택 상태를 다시 확인한다.

설정 이전은 명시적인 초기화 단계로 분리한다. 그리기나 단순 읽기는 설정을 쓰지 않는다. 저장 형식을 유지하고 기존 설정을 보존한다. 잘못된 숫자·알 수 없는 실행 방식·JSON 배열의 비객체 항목은 검증하고 유효한 기본값이나 항목으로 복구한다. 가져온 파일 식별자와 확장자를 검사해 앱 내부 grids 디렉터리의 파일만 처리한다.

회귀 검사는 오래된 객체의 색 변경이 새 파일 목록·회전 값을 되돌리지 않는 경우, 동시에 들어온 추가·삭제, 변환 중 다중 선택 전환, 12개 제한, 손상된 메타데이터, 황금비 선택 이전의 반복 실행을 포함한다.

## 2. 세션 정책과 Android 서비스 연결

별도의 작은 세션 정책 단위에서 최초 안내 완료, 실행 방식, 사용자 중지, 부팅 번호, 실제 수동 서비스 상태를 받아 활성 여부와 다음 동작을 판단한다. 정책은 Android View 없이 단위 검사할 수 있어야 한다.

Activity·카메라 메뉴·알림의 시작/중지/실행 방식 변경은 공통 조정 경로를 사용한다. Android 서비스의 시작·중지는 이 경로에서 수행하며 서비스 콜백으로 실제 실행 상태를 반영한다. service 생성 자체를 알림 준비 완료로 간주하지 않는다.

`CameraWatchService.instance`를 사용하는 제품 호출은 연결 상태·갱신 요청을 담당하는 작은 브리지 뒤로 모은다. 브리지는 연결 종료 시 참조를 해제하고 미연결 상태를 정상적으로 처리한다. 접근성 노드와 WindowManager 동작은 기존 서비스에 유지한다.

알림 권한 요청 중 재생성, 권한 거부, 중지 후 테마·언어 변경, manual→always와 always→manual 전환, 서비스 생성/종료, 다른 부팅 번호, 접근성 미연결을 검사한다. 지연 콜백은 화면·창 수명에 연결하여 닫힌 팝업이나 종료된 Activity를 다시 갱신하지 않는다.

## 3. 설정 갱신과 렌더링

스타일·기하 변경, 메뉴 구성 변경, 세션·외관 변경을 구분한다. 라인 입력은 최신 상태를 반영하되 같은 메인 루프 프레임에 발생한 갱신 요청을 합친다. 단순 색·두께·불투명도 변경은 카메라 트리 탐색과 메뉴 창 재부착을 요구하지 않는다.

SVG picture는 크기·기하·두께·비율 유지·아웃라인처럼 실제 picture에 영향을 주는 속성이 바뀔 때만 무효화한다. 색·불투명도 변경은 기존 그림에 paint를 적용한다. 기본 Path와 키트 아이콘도 필요한 키로 재사용한다.

가져온 파일의 읽기·디코딩·SVG 파싱은 그리기 콜백에서 분리한다. 준비 중에는 해당 파일만 그리기를 보류하고 완료 시 invalidate한다. 크기·선택·파일 삭제·View 분리 이후의 오래된 작업 결과는 폐기한다. Picture 생성과 Canvas 사용은 스레드 경계를 명확하게 유지한다. 렌더링 검사는 준비 완료를 기다린 뒤 픽셀을 판정한다.

진단 상태 파일 기록은 변경 사항이 없으면 생략하며, 명시적 capture 명령은 즉시 최신 상태를 기록한다. 기능 개선을 검증하는 호출 횟수 검사와 캐시 무효화 검사부터 추가한다. 실제 프레임 시간·배터리 개선은 기기 측정 없이 주장하지 않는다.

## 4. 파일 관리와 오류 표시

파일·목록 삭제를 SettingsPanel에서 전용 파일 관리 단위로 옮긴다. 파일 저장 실패 시 임시 파일을 정리하고, 최신 목록 등록에 실패한 새 파일을 남기지 않는다. 삭제 실패를 기록하고 사용자에게 번역된 오류를 알린다. 파일 이름의 표시값과 실제 저장 경로는 구분한다.

가져오기 예외는 파일 열기/크기/개수/형식/변환/저장 오류로 분류해 string 리소스에 연결한다. 파서의 원본 메시지는 사용자 Toast로 노출하지 않고 진단 기록에만 남긴다. 영·한 리소스 키와 서식 인자를 일치시키고 황금비 설명의 문자 `%`를 서식 지정자로 해석하지 않도록 한다.

가져오기 작업은 Activity 종료 후 Toast·카메라 복귀를 실행하지 않는다. 성공·실패 시 카메라 복귀 흐름과 시스템 파일 선택기의 권한 범위를 유지한다. SVG DOCTYPE·ENTITY 거부와 원본 paint 제거는 보존한다.

## 5. 지원 목록과 화면 책임

지원하는 그리드 식별자·이름·설명 리소스를 한 목록에 모은다. 현재 UI에서 사용하지 않는 한국어 이름·설명 배열을 제거한다. 단일 황금비는 이전 입력으로만 취급하고 현재 렌더링 검사도 현재 지원 목록을 사용한다.

SettingsPanel은 탭 구성·입력·표시에 집중하고 저장, 세션, 파일 변경은 해당 단위에 위임한다. 화면 메서드를 읽기 쉬운 형태로 정리하되 불필요한 화면 재작성이나 전면 패키지 분리는 하지 않는다. 선택·스크롤·키보드·예약 공간과 기존 디자인 토큰을 보존한다.

## 6. 테스트 실행과 실패 복원

Redesign-Line-Test는 실제 KitSlider를 찾고 현재 padding 12dp를 사용한다. 이전 진단 자료를 외부 baseline으로 요구하지 않고 실행 시 현재 상태를 읽는다. 활성 검사와 v0.9 보관 검사를 문서에서 구분한다.

기기 검사 공통 준비/복원 도우미를 둔다. 변경 대상 설정은 검사 전 백업하고 성공·실패 모두 finally에서 복원한다. 디버그 전용의 DUMP 보호 명령이 필요한 경우 백업 범위를 앱 설정과 앱 소유 파일로 제한하고 release manifest에 포함되지 않는지 검사한다. 테스트 파일은 자신이 만든 파일만 제거한다.

좌표·배율은 기기의 현재 논리 크기에서 계산한다. 화면 크기·배율·회전을 바꾸는 검사는 해당 값도 복원한다. 진단은 계속 artifacts에 저장하고 Git에서 제외한다. 구문 검사는 실제 기기 UI 검사와 구분해서 보고한다.

## 검증 전략

1. 변경 전 테스트를 확보하고 각 오류에 대해 실패하는 회귀 검사를 먼저 실행한다.
2. Java 단위 검사에 세션 정책·지원 목록·캐시/갱신 판단처럼 플랫폼 독립 로직을 추가한다. SharedPreferences·Android 렌더링·가져오기는 instrumentation에서 실제 구현을 검사한다.
3. 기존 Build 스크립트의 assembleDebug, testDebugUnitTest, lintDebug와 assembleDebugAndroidTest를 실행한다. 단위 검사 신규 실행을 확인한다.
4. PowerShell 전체 구문 검사와 현재 활성 스크립트의 노드 선택·좌표 계산 검사를 수행한다.
5. 연결된 허가된 기기가 있는 경우 설정·외관·세션·파일·카메라 메뉴 검사를 실행하고 복원 결과를 확인한다. 기기를 조작하는 검사의 실행 조건과 영향을 먼저 알린다.
6. 실제 손가락 초점·핀치·셔터 전달과 다른 기종 검증은 자동 검사로 통과했다고 주장하지 않는다. 기기 부재나 미실행은 최종 결과에 남긴다.

## 실행 순서와 검토 지점

사용자 설계 검토 후 상세 구현 계획을 작성하고 별도 검토를 받는다. 구현은 테스트 기반 확보 → 설정·파일 저장 안정화 → 세션 정책·연결 정리 → 갱신·렌더링 분리 → 지원 목록·리소스·문서 정리 순서다. 각 단계가 독립적으로 빌드·검사 가능해야 한다.

현재 기준 버전은 이미 Git에 기록되어 있으므로 새로운 baseline 커밋은 만들지 않는다. 구현 시에는 해당 커밋을 기반으로 격리된 작업 공간을 사용하고 단계별 커밋을 남긴다. 푸시·배포는 이번 요청 범위에 포함하지 않는다.

이 문서는 설계이며 구현 완료나 기기 검증 완료를 뜻하지 않는다.
