# Chrynalogia 구조 안정화 구현 기록

## 적용

기준 `2138e72`에서 `codex/structure-hardening` 브랜치로 현재 체크아웃에 코드를 적용했다. 사용자의 로고 파일 변경·추가 파일은 수정하거나 커밋하지 않았다. 새 라이브러리, 앱 권한, 버전 번호 변경 없이 Java·네이티브 View와 기존 UI를 유지했다. 접근성 오버레이 타입과 터치 전달 플래그, PreviewLocator는 유지했다.

테스트 복원, 변경 항목 저장과 검증, 파일 트랜잭션, 세션 정책, 프레임 갱신·비동기 파일 준비, 지원 목록 통합을 단계별 커밋으로 기록했다. `artifacts/hardening`은 Git에서 제외되는 상세 실행 로그·사용자 상태 백업 비교용 기록이다.

## 검증

- 단위 검사 15개: 기하 5, 대비 2, 세션 정책 4, 프레임 갱신 1, 변경 분류 2, 지원 목록 1.
- S23 / SM-S911N 계측 64개: 현재 지원 그리드·변형·가져오기 렌더링 36, 설정 8, 파일 처리 11, 실제 세션·Activity 재생성 4, 캐시·비동기 종료 5.
- PowerShell 동작·구문 검사 34개. UI 슬라이더 fixture는 현재 KitSlider, 배율, 숨김·탐색 바 가림을 검사한다. 본문과 복원 실패가 함께 발생해도 모든 복원을 실행한다.
- debug 및 AndroidTest APK 빌드, release main manifest 생성, lint 오류 0. 기존 Gradle 버전 안내 경고 1개는 남아 있다.
- 테스트 전후 앱 설정 복원 명령이 result=0으로 완료됐다. 전체 계측은 앱 프로세스를 종료한다. 기기의 접근성 활성 목록에 Chrynalogia가 없어 카메라 위 UI 검사는 실행하지 않았으며 새로 허용하지 않았다.
- 실제 손가락 입력, 다른 기종, 모든 촬영 모드 조합, 프레임 시간·배터리 측정은 미실행이다. 작업량 감소와 캐시 재사용을 실제 성능 수치로 표현하지 않는다.

실패를 확인한 회귀 사례: 오래된 설정 저장이 회전 값을 되돌림, 새로운 세션 정책 부재, 프레임 갱신·분류 부재, SVG 색 변경이 Picture를 초기화함, 동일 아이콘을 매번 파싱함, 폐기된 단일 황금비의 내부 지원. 수정 후 관련 검사를 통과했다.

## 실행 중 판단

1. 사용자가 반복 승인 요청 후 직접 코드 적용을 지시했으므로 계획 승인과 Native 실행 지시로 해석하고 추가 승인 단계를 중단했다.
2. 사용자가 보는 현재 체크아웃의 전용 브랜치에서 적용했다. 별도 worktree로 결과를 남겨 다시 전달하지 않는다. 비용: 파일 시스템 격리가 없으므로 사용자 작업과 충돌하지 않게 경로별로 커밋했다.
3. Windows에서 실행 ledger·로그는 이미 제외된 `artifacts/hardening`에 저장했다. Bash 전용 실행 도우미를 사용하는 대신 동일한 순서와 테스트 기록을 유지했다.
4. 기존 네이티브 입력 리스너는 변경 항목 패치를 사용하고, 선택·파일 작업은 최신 상태 갱신을 사용한다. 비용: 같은 항목의 의도적인 동시 변경은 마지막 저장이 우선한다. 관련 없는 필드는 덮어쓰지 않는다.
5. 비동기 대기 코드는 테스트 유틸리티에 두고 제품 클래스는 준비·캐시 상태를 진단으로 제공한다. 공유 비트맵을 캐시에서 제거할 때 살아 있는 View가 사용하는 비트맵을 recycle하지 않는다. 비용: 실제 메모리 해제 시점은 GC가 결정한다.
6. 현재 장치에서 접근성 연결이 활성화되지 않은 것을 확인했으므로 UI 검사의 사전 조건으로 보고 임의로 새 접근성 권한을 켜지 않았다. 비용: 카메라 메뉴·팝업 UI 동작은 연결 후 추가 검증이 필요하다.

독립 코드 리뷰는 별도로 진행하고 중요한 발견은 수정과 회귀 검사 결과를 이어서 기록한다.
